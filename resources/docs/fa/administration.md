هر نصب یک **پنل مدیریت** روی `/admin` دارد. این پنل برای کسانی است که سرویس را اداره می‌کنند: رسیدگی به گزارش‌ها، مسدود کردن حساب‌های متخلف، مدیریت کلیدهای API و دیدن میزان استفاده از سرویس. کاربران عادی آن را نمی‌بینند؛ برایشان `/admin/api` فقط `404` برمی‌گرداند.

## ساختن اولین مدیر

```bash
php artisan admin:create you@example.com --name="Your Name"
```

یک گذرواژه ساخته و فقط همان یک بار نشان داده می‌شود (با `--password=` می‌توانید خودتان انتخاب کنید). با کد ایمیلی هم می‌شود وارد شد. بعداً:

```bash
php artisan admin:grant someone@example.com             # یک کاربر موجود را مدیر کن
php artisan admin:grant someone@example.com --revoke    # دسترسی را بردار (هرگز آخرین مدیر)
```

بعد `/admin` را باز کنید (یا از منوی حساب روی **پنل مدیریت** بزنید).

## چه کارهایی می‌شود کرد

| بخش | کاربرد |
|---|---|
| **داشبورد** | کاربران، پروفایل‌های عمومی، عکس‌ها، درخواست‌ها، حساب‌های تأییدشده، سایت‌ها و گزارش‌های باز؛ نمودار رشد و ترافیک ۳۰ روزه؛ سایت‌هایی که بیشترین استفاده را دارند؛ و بررسی سیستم که درباره تنظیماتی که روی سرور واقعی غلط‌اند هشدار می‌دهد (روشن بودن debug، فقط‌لاگ بودن ایمیل، صف `sync` و…). |
| **کاربران** | جست‌وجو با نام، ایمیل، نام کاربری یا شناسه؛ فیلتر مدیران، مسدودها، ایمیل تأییدنشده و صاحبان سایت. یک پنل کناری همه‌چیز درباره‌ی کاربر را نشان می‌دهد و اقدامات زیر را در اختیار می‌گذارد. |
| **گزارش‌ها** | بازدیدکننده‌ها می‌توانند پروفایلی را گزارش کنند (هرزنامه، جعل هویت، محتوای نامناسب، محتوای غیرقانونی، سایر). هر گزارش را بررسی کنید، با یادداشت «رسیدگی شد» یا «رد شد» بزنید، همه‌ی گزارش‌های باز همان پروفایل را یک‌جا ببندید، یا یکی را دوباره باز کنید. |
| **سایت‌ها و کلیدها** | همه‌ی سایت‌های متصل: مالک، آخرین استفاده، سقف درخواست. کلید را غیرفعال کنید، سقف را عوض کنید یا سایت را حذف کنید. |
| **حساب‌های تأییدشده** | جست‌وجو در همه‌ی وب‌سایت‌ها، گیت‌هاب‌ها و تلگرام‌های تأییدشده و لغو تأیید. |
| **گزارش عملیات** | همه‌ی کارهای مدیران، از جدید به قدیم. |

### اقدامات روی یک کاربر

- **مسدود کردن**: دلیل لازم است. کاربر در درخواست بعدی‌اش از حساب خارج می‌شود، پروفایل، خروجی‌ها و آواتارش از همه‌جا (از جمله [API](/docs/api-reference)) محو می‌شود و کلیدهای API او کار نمی‌کنند. با رفع مسدودی همه‌چیز برمی‌گردد.
- **تغییر نام کاربری**، **برداشتن عکس** (یا کل آرشیو عکس‌ها)، **پاک کردن محتوای پروفایل** (بیوگرافی، عنوان، موقعیت، وب‌سایت، لینک‌ها، شبکه‌ها، نام‌ها)، **ارتقا یا برداشتن دسترسی مدیر**.
- **حذف**: حساب، پروفایل، عکس‌ها، ایمیل‌ها، کلیدها، آمار و گزارش‌ها برای همیشه پاک می‌شود. برای تأیید باید ایمیل کاربر را تایپ کنید.

هرگز نمی‌توانید خودتان یا مدیر دیگری را مسدود یا حذف کنید و هیچ‌کس دسترسی مدیر خودش را نمی‌تواند بردارد. اول دسترسی مدیر دیگر را بردارید، بعد روی حسابش اقدام کنید.

## گزارش عملیات

هر تغییر بالا ثبت می‌شود: چه کسی، کی، روی چه چیزی و با چه جزئیاتی (مثلاً دلیل مسدودی). ایمیل مدیر حتی اگر حسابش بعداً پاک شود در ثبت می‌ماند و پنل راهی برای ویرایش یا حذف ثبت‌ها ندارد.

## گزارش‌های بازدیدکننده‌ها

هر صفحه‌ی عمومی یک پیوند **گزارش این پروفایل** دارد (برای صاحب پروفایل نشان داده نمی‌شود). فرم یک دلیل و یک توضیح اختیاری می‌گیرد. برای جلوگیری از تکرار فقط یک **هش کلیددار** از IP گزارش‌دهنده را ۲۴ ساعت نگه می‌داریم، نه چیز دیگری، و صفحه چه گزارش ذخیره شده باشد چه نه یک پاسخ می‌دهد. از هر آدرس در دقیقه حداکثر شش گزارش پذیرفته می‌شود.

## نکته‌های امنیتی

- پنل مدیریت همان برنامه‌ی تک‌صفحه‌ای است، ولی **هر** اقدام از `/admin/api` می‌گذرد که پرچم مدیر را برای هر درخواست روی سرور بررسی می‌کند.
- ایمیل کاربران برای مدیران قابل‌مشاهده است، چون کار لازم دارد. کلیدهای API **هرگز** نشان داده نمی‌شوند: فقط یک پیشوند کوتاه.
- گذرواژه‌ی قوی و یکتا بگذارید و دسترسی به `/admin` را در وب‌سرور هم محدود کنید (مثلاً با IP).
